# 环境配置

## 本地入口

| 应用       | 默认地址                            | 配置位置                                        |
| ---------- | ----------------------------------- | ----------------------------------------------- |
| 管理端     | `http://localhost:5174`             | `apps/admin/.env`，公开变量使用 `VITE_*`        |
| 小程序 H5  | `http://localhost:5173`             | `apps/miniapp/.env.local`，公开变量使用 `APP_*` |
| 后台 API   | `http://localhost:3000/api/admin`   | `apps/api/.env`                                 |
| 小程序 API | `http://localhost:3000/api/miniapp` | 目前仅模块入口，业务接口尚未实现                |
| PostgreSQL | `127.0.0.1:15432`                   | 根 `.env` 供 Docker Compose 使用                |

管理端与小程序 H5 固定端口，端口占用时直接报错。API 的默认 CORS 白名单允许这两个 localhost 来源；使用其它主机名或端口时显式修改白名单。

## 初始化与补缺

在根目录运行 `node scripts/setup.mjs`，会创建缺失文件、补齐缺失配置项以及空的必需设置，保留已有非空值、注释、密码和密钥。可选的空文案配置保持为空。

- 纯空白的必需值视为空；有效密码的前后空格保留。端口只接受范围内的十进制整数字符串，初始化与 API 校验一致。
- 根 `.env`、API `.env`、管理端 `.env` 和小程序 `.env.local` 分别检查，不因某个文件存在而跳过其它文件。
- 新环境为数据库、访问令牌、刷新令牌和初始种子账号生成随机秘密。
- 根配置缺失时，可以从现有本地 PostgreSQL 连接串恢复 Compose 用户和密码；两处已有凭据不一致时停止，不自动更换数据库密码。
- 新写入 Compose 的含 `$` 配置使用单引号字面量，避免被环境变量替换。含单引号或末尾反斜杠等无法同时由 Compose 和 Node 原样读取的组合会在写入前报错，保留原文件和凭据。
- 已有访问密钥但缺少刷新密钥时，补入相同值以保留原回退签名语义；主动轮换密钥应单独操作。
- 已有小程序 `.env` 中的 API 地址和 AppID 会沿用，`.env.local` 优先。初始化默认仍为游客 AppID，不代表已经配置真实微信账号。
- `.local/credentials.txt` 只在缺失时生成；内容是初始种子密码，不代表后来修改过的当前账号密码。脚本不访问数据库，也不会重置账号密码。
- 不自动改写已有端口、CORS、公开地址或前端地址；变更这些配置时按下文同步调整。

示例文件不含实际秘密，实际 `.env*` 和 `.local` 已被 Git 忽略。

## API 配置

所有 API 运行配置在 `apps/api/src/config/env.ts` 读取和校验；进程环境变量优先于 `apps/api/.env`，空字符串或纯空白使用默认值，必需项为空则报错。

| 变量                       | 默认值或要求                                  | 用途                                                                                                                |
| -------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`                 | `development`，可为 `test`、`production`      | 由运行环境指定，不在初始化文件中固定                                                                                |
| `DATABASE_URL`             | 必填 PostgreSQL URL                           | 业务数据库，Prisma CLI 与 API 使用同一校验规则                                                                      |
| `DATABASE_TEST_URL`        | 测试时必填                                    | 仅允许 PostgreSQL 的 localhost/127.0.0.1:15432/app_template_test，不接受查询参数或片段；建库及 API 测试共用入口校验 |
| `JWT_SECRET`               | 必填                                          | 访问令牌签名密钥                                                                                                    |
| `JWT_REFRESH_SECRET`       | 未提供时使用 `JWT_SECRET`                     | 刷新令牌签名密钥；新环境生成独立随机值                                                                              |
| `JWT_EXPIRES_IN`           | `15m`                                         | 访问令牌时长，登录和刷新签发均生效                                                                                  |
| `REFRESH_EXPIRES_IN`       | `30d`                                         | 勾选记住我时的新刷新会话时长                                                                                        |
| `REFRESH_EXPIRES_IN_SHORT` | `1d`                                          | 未勾选记住我时的新刷新会话时长                                                                                      |
| `HOST`                     | `127.0.0.1`                                   | 监听 IP 或 localhost；需要其它网络访问时按实际链路配置                                                              |
| `PORT`                     | `3000`                                        | 1～65535 的整数                                                                                                     |
| `CORS_ORIGINS`             | `http://localhost:5174,http://localhost:5173` | 逗号分隔的 HTTP(S) 来源，只含协议、主机和端口，不支持 `*` 或业务路径                                                |
| `PUBLIC_API_URL`           | `http://localhost:<PORT>`                     | 公开资源 URL 前缀，可带部署子路径，不能包含凭据、查询参数或片段                                                     |
| `TRUST_PROXY_HOPS`         | `0`                                           | 0～255 的整数；0 不信任转发头，其它值按真实代理链设置                                                               |
| `DEMO_MODE`                | `false`                                       | 后台演示只读开关，只接受 true/false                                                                                 |
| `THROTTLE_ENABLED`         | `true`                                        | 后台认证限流开关，只接受 true/false；HTTP 测试显式关闭                                                              |
| `SEED_ADMIN_PASSWORD`      | 首次 seed 时必填                              | 种子脚本使用，运行中的 API 不依赖此值；已有管理员密码不会重置                                                       |

有效期支持正整数秒数或 s/m/h/d 单位，例如 `900`、`15m`、`2h`。进入 JWT 库前统一转换为数值秒，避免数字字符串被解释成毫秒。刷新轮换保留已有会话的到期时间，不因修改配置无限延长旧会话。

## 前端配置与修改步骤

管理端使用 `VITE_API_BASE_URL`，小程序使用 `APP_BASE_URL`；两者都是公开配置，不能包含服务端密钥。两端按 Vite 原生模式加载环境文件：进程环境变量优先，其次模式文件（如 `.env.production.local`、`.env.production`），再到 `.env.local`、`.env`。

1. 修改 API 监听端口后，同步检查 `PUBLIC_API_URL`、管理端和小程序的请求基础地址。初始化脚本会为缺失项生成匹配地址，但不会覆盖已有自定义值。
2. 修改浏览器前端端口或主机名后，同步修改 `CORS_ORIGINS`。例如 localhost 与 127.0.0.1 是不同来源。
3. API 环境变更后重启 API，Vite 环境变更后重启开发服务或重新构建前端。
4. 部署时通过进程环境提供服务端配置，并在前端构建时提供相应公开变量；不要把 `.env` 或实际密钥提交到仓库。

`pnpm test:setup` 验证配置补缺、重复运行、凭据保留与测试库入口。密码用例使用临时目录和 `docker compose config --environment` 核对真实解析结果，需要 Docker Compose CLI，但不启动容器；建库流程使用命令替身，不访问数据库。API 测试覆盖配置校验、跨域预检及实际令牌有效期。
